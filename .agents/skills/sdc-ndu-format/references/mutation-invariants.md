# Mutation invariants

## Minimal change rule

- 更新対象のキーとフィールドを先に列挙する。
- 数値トークンの前後にある空白を保持する。
- 元の改行コードを保持する。
- 対象外の行、コメント、未知レコード、レコード順を保持する。
- 空欄と `0` を区別する。
- 同値の数値表記を理由なく正規化しない。

## Preflight before writing

書込み前に少なくとも次を完了する。

1. SDC の CP932 デコードと対象セクションの一意な検出
2. 方向・計算ケース・条件・列方言の確定
3. NDU の必須キーと対象レコードの一意な検出
4. KG → 部材 → 節点 → 座標の参照整合
5. 杭形状、杭長、SDC 深度範囲の整合
6. 対象フィールドの個数・型・既存支持との競合検査
7. 変更計画と差分の生成

検証途中でファイルを書き始めない。

## Support invariants

- `SuppotNum` と `SuppotRow` は `SuppotInfo` 件数に等しい。
- `SuppotInfoN` は1から連続する。
- `Suppot_ChokuKisoCaseNoN` も支持項目番号に対して1から連続する。
- 新しいケース行は `=0` で追加する。
- 既存の非ゼロケース値は保持する。
- 対応支持のない非ゼロケース行は削除しない。
- 現行処理では `ShitenCaseNum=0` を要求する。
- 同一節点・方向2の重複支持や、対象節点を覆う範囲支持は自動マージしない。
- 抵抗ゼロの節点に既存支持があっても自動削除・再採番しない。

## Output safety

- 既定は別名出力にする。
- 同名上書きを許す場合も、読み込み時のバイト列が書込み直前まで同一であることを確認する。
- 上書き時は復元可能なバックアップを作る。
- 一時ファイルに完全な結果を書き、検証後に置換する。
- 失敗時に元ファイルと半端な出力が混在しないようにする。

## Abort conditions

次は警告だけで続行せず、中止する。

- 未知または複数候補の見出し・方向・計算ケース・列割当
- 選択処理間の地震時／液状化時の混在
- 傾斜杭、突き出し、節点重複、部材の切れ・重なり
- SDC の層欠落、層重複、列不足、杭長不一致
- NDU の必須キー重複、フィールド不足、参照先欠落
- 対象に重なる範囲支持、同じ節点の重複 Y 支持
- 杭先端で未配賦の正の周面抵抗
- 複数支持ケース、または孤立した非ゼロケース行
- 杭先端に既存する非ゼロの水平・回転ばねなど、上書き意味が不明な競合

## Post-write verification

1. 出力を再読込みする。
2. 対象値が計画どおりであることを確認する。
3. NDU の支持件数・連番・ケース行の不変条件を再確認する。
4. 対象外バイトが変わっていないことを差分で確認する。
5. 関連する単体テストを実行する。
6. 形式共通部を変更した場合は全テストを実行する。
