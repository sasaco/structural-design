# Scope and evidence

## Scope

この知識は、このアプリが扱う `.sdc` と `.ndu` の**対応済み部分集合**を記述する。
ファイル形式全体や、作成元ソフトの全バージョンを網羅する公式仕様ではない。

現在の主対象は次の4処理である。

1. 水平地盤ばね: SDC → `JibanShogenInfo` の水平ばね
2. 地盤反力度: SDC → `JibanShogenInfo` の上端・下端反力度
3. 杭周面支持: SDC → 複数の `SuppotInfo`
4. 杭先端支持: SDC → 杭先端節点の `SuppotInfo`

現行の製品対象は `.ndu` とする。`.ndt` は過去の検討資料に現れる歴史的な形式名であり、現行処理の対応形式として一般化しない。Excel 出力は NDU から派生する確認・帳票機能であり、SDC/NDU 形式そのものではない。

## Confidence labels

知識を追加・説明するときは、次のラベルを使い分ける。

| Label | Meaning |
|---|---|
| `confirmed` | 複数の実データ、実装、テストが一致している |
| `verified` | コミット済み実装に回帰テストがある |
| `worktree-verified` | 未コミットの作業ツリー実装にテストがある。コミットまでは固定仕様とみなさない |
| `observed` | 特定の実ファイルまたは画面で観測した |
| `inferred` | 観測結果から推定したが、独立した裏付けが不足している |
| `unknown` | 意味または一般性を確定できていない |

## Evidence priority

矛盾がある場合は、次を組み合わせて判断する。単一の資料だけで形式全体を断定しない。

1. ユーザーが今回明示した要件
2. 再現可能な実ファイルと期待結果
3. 回帰テストと fixture
4. 現在の実装
5. 過去の設計資料・実装履歴
6. コメント、命名、単一ファイルからの推定

固定行番号や、1モデルだけの節点番号は仕様の根拠にはなるが、一般仕様ではない。モデル固有の事実は `imacho-4p-example.md` のように分離する。

## Non-goals

- 未知の SDC 見出しを類似文字列で推測すること
- NDU の全キーまたは全フィールドの意味を推定すること
- 既存の NDU 値に合うよう SDC 計算式を逆調整すること
- 実例が1件しかない振る舞いを無条件に他モデルへ一般化すること
