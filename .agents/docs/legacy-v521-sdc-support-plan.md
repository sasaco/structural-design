# Ver.5.2.1共有値SDC対応計画

作成日: 2026-09-18

状態: 実装済み。専用テストおよび外部fixture非依存の回帰テストで `worktree-verified`。

## 1. 目的

次の2案件のSDCを、現行のSDC Converterで橋軸方向・直角方向とも使用できるようにする。

- `tests/testdata/札幌駅P2橋脚/P1_φ1.3_L10.0(fr_載荷試験).sdc`
- `tests/testdata/品川(東タ)道路P6/東タ改良 P6橋脚(No.4).sdc`

対象は現行アプリの4処理である。

1. 水平地盤ばね
2. 有効抵抗土圧力
3. 杭周面ばね・支持力
4. 杭先端ばね・支持力

GUI、共通API、単独CLI、計算記録JSON、計算過程Excelまで同じ解釈を通す。SDC原本を新形式へ書き換える方式は採らず、CP932の原バイトを入力として旧方言を明示的に解釈する。

## 2. 対応範囲の定義

今回対応するのは「旧SDC全般」ではない。2案件で共通して観測できた次の方言を、`Ver.5.2.1共有値方言`として限定対応する。

- バージョン情報が正確に `Ver.5.2.1`。
- a表の杭列数は方向ごとに存在する。
- 水平、周面、先端の値は杭列別に反復せず、選択方向の全杭列が1組の値を共有する。
- 土圧だけは `1列目`、`2列目`、`3列目以降` の3区分を持つ。
- 表の値はSDC記載どおり使用し、奥行き本数を再乗算・再除算しない。

バージョン文字列だけで受理しない。各表の表題、単位、結合見出し、CSV欄数が本書の形と完全に一致したときだけ旧方言として扱う。新旧形式が部分的に混在する入力、似た名称、欄数不足は推測で補わず拒否する。

## 3. 調査した入力

### 3.1 原本の識別

SHA-256は調査時点の原本確認用であり、実装の分岐条件には使わない。

| 入力 | 行数 | バイト数 | SHA-256 |
| --- | ---: | ---: | --- |
| 札幌 SDC | 266 | 10,326 | `65313bb701e71c58d3226bf7a2f1d2532bc30fafda1f1083f604eed808e57502` |
| 札幌 線路方向NDU | 538 | 16,280 | `9f7660b3f19395647afec7c5b08a2a61804ff6038324be2bf88a84cd9e4e306b` |
| 札幌 直角方向NDU | 937 | 30,171 | `22531d89edbe8e2169dbb17fcff960a8d46d644e23c13865ef37bdf52ccc887f` |
| 品川 SDC | 252 | 9,413 | `cbef55b93fe8d6385953722527aee65db7a818d4fafba7a14e84e9a6418fa2b2` |
| 品川 線路方向NDU | 757 | 24,272 | `b4b1288c61e16b39ffe8bd10be91ed28b6375b25eacbf192ed850d0d1d182895` |
| 品川 直角方向NDU | 843 | 26,779 | `7ecc029b0342c6a6231aaf80c904861852f6f0a1916b59a13de2f03e8d927ef7` |

4本のNDUはGitのインデックスから同じパスへ復元し、上表は作業ツリー上のCRLFバイト列を
再計測した値である。SDCとNDUの正規ペアとして使用する。`.sdr`、`.sdt`は今回の変換・検証には
使わず復元しない。

### 3.2 方向、杭列、NDU形状

| 案件 | 方向 | SDC杭列数 | NDUのKG | 1 KGの杭長 |
| --- | --- | ---: | --- | ---: |
| 札幌 | 橋軸 | 2 | KG1～2 | 12.000 m |
| 札幌 | 直角 | 3 | KG1～3 | 12.000 m |
| 品川 | 橋軸 | 2 | KG1～2 | 26.500 m |
| 品川 | 直角 | 2 | KG1～2 | 26.500 m |

4本のNDUはすべて現行`parse_ndu()`で読める。各KGについて`KGInfo → ElementInfo → JointXY`の鉛直性、連続性、杭長も検証済みである。NDU側の形式不良は今回の障害ではない。

### 3.3 実装前パーサーの停止点

両SDC、両方向で同じ理由により停止する。

| 処理 | 現在の停止理由 |
| --- | --- |
| 水平 | `短期(非線形)-N列目`または奇数・偶数列を期待するが、旧表は単独の`短期(非線形解析)`しか持たない |
| 土圧 | `3列目以降奇数列`／`4列目以降偶数列`を期待するが、旧表は単独の`3列目以降`を持つ |
| 周面 | 杭列見出し行を期待する位置から最初のデータ行を読み、数値を列名として解釈して停止する |
| 先端 | 杭列見出し行と明示的な第1・第2勾配見出しを期待するが、旧表は見出しを省略して値を直後に置く |

`kg_candidates.inspect_candidates()`も水平パーサーを入口にするため、現在はGUIのKG候補表示より前に停止する。

## 4. 旧方言の正規化ルール

原SDCの行を合成・書換えして現行パーサーへ渡すのではなく、各パーサーが原行から共通の内部モデルへ変換する。これにより計算記録のSDC行・CSV欄を原本に正しく戻せる。

### 4.1 共通の共有列レイアウト

`scripts/sdc_columns.py`に、杭列数`N`と1個の元欄から次を作る厳格な共有レイアウトを追加する。

```text
実杭列 1..N -> 同じ元CSV欄
ColumnLayout.kind = "shared"
SourceColumn.interpretation = "v5.2.1-shared"
```

任意の空見出しを共有列とみなしてはならない。呼出し元が対象表の完全な旧見出しとバージョンを確認した後だけ共有レイアウトを生成する。

また、バージョン情報を一意に読む共通ヘルパーを追加する。`Ver.5.2.1`以外へ今回の省略規則を広げない。既存の番号列、奇数・偶数列、pressure-parityの動作は変更しない。

### 4.2 水平地盤ばね

旧表の見出しは次の5欄である。

```text
層番,層厚(m),水平方向ばね値(kN/m2)
,,長期,短期(線形解析),短期(非線形解析)
```

CSV第5欄の`短期(非線形解析)`を、方向内の実杭列1～Nすべてへ共有する。条件は地震時とし、出典は各層の原行・第5欄を保持する。

層境界をまたぐ部材の長さ加重平均、整数`ROUND_HALF_UP`、NDUの`JibanShogenInfo`第2欄だけを更新する現行規則は変更しない。

### 4.3 有効抵抗土圧力

旧表の列区分を次のように展開する。

| 原見出し | CSV欄 | 実杭列 |
| --- | --- | --- |
| `1列目` | 3／4 | 1 |
| `2列目` | 5／6 | 2 |
| `3列目以降` | 7／8 | 3以上 |

内部のレイアウト種別は`pressure-tail`とし、`3列目以降`を奇数・偶数へ分けない。今回の実データは杭列数2または3である。杭列数2の場合も原表に第3区分が残るため、その未使用区分は上下とも0であることを検証する。実例のない4列以上は初回実装では拒否し、別fixtureと意味確認を得てから拡張する。

応答変位法以外／応答変位法の選択、層内線形補間、層境界の積分平均、小数1桁`ROUND_HALF_UP`は変更しない。GUIの直接列指定も再反転しない。

### 4.4 杭周面ばね・支持力

旧d/e表は杭列見出し行を持たず、次の値を全杭列で共有する。

| 採用量 | 原表のCSV欄 |
| --- | ---: |
| 押込み側・短期第1勾配 K1 | d表 第6欄 |
| 押込み側・降伏点 Fy | e表 第4欄 |
| 有効長`⊿l` | d表 第5欄、e表 第3欄 |

d表は1行7欄、e表は1行5欄であることを固定検証する。既存の杭長、突出長0、根入れ深さ、`1/β`、全層厚、最終層の厚さ0、押込み有効区間の検証を維持する。

値の展開後は現行の`existing-screen`方式を使い、節点負担区間でK/Fを積分する。Kは整数、Fは小数1桁へ最後に丸める。引抜き側や第2勾配を新たな選択肢にはしない。

### 4.5 杭先端ばね・支持力

旧f表の鉛直値は次の3欄だけを持つ。

```text
長期,短期
長期K,短期K1,短期K2
```

採用規則は次のとおりで、全杭列が同じ元欄を共有する。

| 採用量 | CSV欄 |
| --- | ---: |
| K1 | 2 |
| K2 | 3 |
| Fy | g表 1 |
| Fu | g表 2 |

水平・回転先端ばねは`長期,短期`に続く2値がすべて0であることを確認する。省略見出しの解釈種別は`tip-v5.2.1-shared-omitted-headings`としてJSONへ残す。

NDUへの10欄配置は現行の`TipValues.fields()`を変更しない。空欄と0も区別する。

## 5. NDUを期待値として使う範囲

4本のNDUを完全バイトgoldenにはしない。調査結果に基づき、検証対象を次のように分ける。

### 5.1 完全一致に使えるもの

- 水平ばねは札幌橋軸24/24、札幌直角36/36、品川橋軸50/50、品川直角50/50部材が、旧SDCの共有値と現行の長さ加重平均で完全一致する。
- 品川の土圧は右押し列順`1:2 2:1`と積分平均で、橋軸・直角とも50/50部材が完全一致する。
- 先端支持は全対象杭で、正側のK1、Fy、K2、Fu、K3がSDC原値と一致する。

### 5.2 参照限定とするもの

- 札幌の土圧は右押し列順が最良だが、橋軸10/24、直角15/36部材だけが完全一致し、最大差はそれぞれ76.3、60.7である。表示丸めだけでは説明できないため、既存NDUへ逆合わせする補正は加えない。
- 既存NDUの先端支点は、先端値に周面側の負側抵抗を合成した10欄を持つ。現行アプリはこの合成規則を仕様化していないため、支点全欄の一致や出力NDUのバイト一致を要求しない。
- 現行`existing-screen`方式で生成した周面10欄も、既存NDUの全欄とは一致しない。計算式と原SDC欄から独立期待値を作り、更新対象以外のバイト保持を検証する。

参照NDUの値を使ってSDC計算値を補正しない。未解明の差は明示したままにする。

## 6. コード変更方針

| 対象 | 変更内容 |
| --- | --- |
| `scripts/sdc_columns.py` | SDCバージョンの厳格な取得、共有列レイアウト、`pressure-tail`レイアウトを追加 |
| `scripts/fill_jiban_shogen.py` | Ver.5.2.1水平表の完全一致分岐と共有値・出典の展開 |
| `scripts/fill_jiban_pressure.py` | `3列目以降`形式の解決、杭列数2時の未使用ゼロ対検証、出典保持 |
| `scripts/fill_suppot_info.py` | 杭列見出し省略d/e表の専用読取、共有K1/Fyの展開 |
| `scripts/fill_pile_tip_suppot_info.py` | f/g表の省略見出し専用読取、共有K1/K2/Fy/Fuの展開 |
| `scripts/kg_candidates.py` | 共有水平表から実杭列1～Nを候補として返すことを確認。専用分岐はパーサー側に限定 |
| `scripts/calculation_record.py` | 新しい`SourceColumn.interpretation`をそのまま記録し、共有元欄を重複生成しないことを確認 |
| `scripts/excel_report.py` | 同じ原行・原欄を共有する杭列が同じ原値セルを参照することを確認。レイアウト変更は原則不要 |
| `scripts/portable_converter.py`、GUI、単独CLI | 新しい選択肢は追加せず、既存の方向・土圧区分・KG列指定をそのまま通す |

ファイル名や案件名から方言、方向、KG、押し方向を推測しない。判断材料はSDC内のバージョンと表構造、利用者が選択した方向・列だけとする。

ユーザー向け機能追加として配布する場合は、現行`1.4.0`から`1.5.0`へマイナー更新し、EXE/ZIPを再構築する。

## 8. テスト計画

### 8.1 専用テスト

`tests/test_legacy_v521_sdc.py`を新設し、次の4組を表形式で検証する。

| ケース | SDC方向 | NDU | GUI右押し相当の直接列指定 |
| --- | --- | --- | --- |
| 札幌・線路 | `longitudinal` | `P1_線路.ndu` | `1:2 2:1` |
| 札幌・直角 | `transverse` | `P1_直角.ndu` | `1:3 2:2 3:1` |
| 品川・線路 | `longitudinal` | `線路方向.ndu` | `1:2 2:1` |
| 品川・直角 | `transverse` | `直角方向.ndu` | `1:2 2:1` |

各組で次を確認する。

1. 4パーサと土圧2区分が正常に読み込める。
2. 実杭列数、層数、層厚合計、杭長、条件`seismic`が独立期待値と一致する。
3. 各実杭列の値と`SourceColumn`が同じ原CSV欄を正しく共有する。
4. `kg_candidates.inspect_candidates()`が全KGを長さ一致の候補にする。
5. `portable_converter.prepare()`で4処理を一括実行できる。
6. 入力SDC/NDUのハッシュが実行前後で変わらない。
7. 出力を再読込みでき、更新対象外の行・フィールド・空白・改行を保持する。
8. JSONとExcelの原値、出典行・欄、方言解釈名が同じである。

4処理の想定プレビュー件数は、札幌線路66、札幌直角99、品川線路138、品川直角138である。実装時に水平・土圧の部材数、周面節点数、先端節点数へ分解して照合し、単に総数だけを固定しない。

### 8.2 NDU参照照合

- 第5章の完全一致範囲だけを厳密assertionにする。
- 札幌土圧は最良列順と差分統計を記録するが、既存NDU値への一致を合格条件にしない。
- 先端は正側5欄を照合し、負側合成欄は「既存値を計算式の根拠にしない」ことをテスト名とコメントで明示する。
- 出力全体のSHA-256固定は行わず、対象値と対象外バイト保持を検証する。

### 8.3 不正入力

合成fixtureで次を拒否する。

- `Ver.5.2.1`以外で省略見出しだけを持つ入力。
- バージョン見出しの欠落・重複。
- 旧水平表の5欄以外、採用欄の欠落、負値、NaN、Infinity。
- 土圧の`1列目`／`2列目`／`3列目以降`の欠落・重複・並び違い、上下逆転、非ゼロの未使用区分。
- 杭列数1、4以上を今回の旧方言へ与える入力。
- d/e表の欄数不一致、K1/Fy/`⊿l`の不整合、全層厚や杭長の不一致。
- f/g表の値不足・余剰、水平または回転先端ばねの非ゼロ、Fu＜Fy。
- 1つの方向内で旧共有形式と番号列・奇偶列形式が曖昧に混在する入力。
