# 左SDC対応の実装・検証記録

実装日: 2026-09-18。対象バージョン: SDC Converter 1.3.0。

[承認済み計画](left-sdc-support-plan.md) に基づき、指定された `test/今町橋りょう4P(左).sdc` を原本のまま使用できるようにした。4項目の計算、NDU保存、JSON、主表5シートのExcel、GUIプレビュー、個別CLI、配布EXEまで確認済み。

## 実装内容

`scripts/sdc_columns.py` に実杭列数・見出しの解決を集約した。番号列形式は従来の対応を保持し、奇数／偶数形式は配置表の実杭列数まで展開する。土圧の「1列目」「2列目」「3列目以降奇数列」「4列目以降偶数列」は4つの値の区分として扱う。左SDCでは実杭列が3列なので、選択可能な列も1～3となる。

4つのパーサーは、計算用の値に加えて `SourceColumn`（元CSVの欄番号・見出し・解釈種別）を保持する。行番号は従来どおり各層・表が保持する。水平・土圧では配置表を持たない従来の番号列の部分入力にも対応するが、奇偶形式では実杭列数を必須とする。

周面は表の種類数2と実杭列数を区別し、全層厚・有効層厚、1/β・先端除外を既存計算へ渡す。計算方式・丸め・既存画面方式は変更していない。

先端は明示された勾配見出しを読む通常形式に加え、Ver.5.2.3の鉛直ばねで「長期,,短期」「奇数列,偶数列」の2回反復と正確に6個の数値を持ち、支持力表も奇偶形式となる場合に限り、省略された勾配見出しを解釈する。長期2欄、短期K1の2欄、短期K2の2欄という対応は、既存snap NDUの左先端3支点・全10欄との一致で裏付けた。原SDCへの書き換えは行わない。

`calculation_record.py` はパーサーが保持した出典を使用する。CSV見出しの再検索や実杭列数からのCSV欄の逆算を廃止し、採用値と元CSVの値も記録時に照合する。出典の識別キー `(処理, 行, CSV欄)` を保持するため、左SDCの奇数列は実杭列1/3で共有され、右SDCの同値・別欄の原値は独立する。既存のExcel原値参照処理で扱えるため、帳票レイアウト・計算式の変更は不要だった。

JSONの既存キーの意味は維持し、出典に `interpretation` を追加した。先端の省略見出しは `tip-parity-omitted-gradient-heading` と記録される。個別先端CLIのJSONにも各量の元CSV欄・解釈種別を追加した。JSONスキーマ番号は1を維持した。

GUIの番号列選択、押す側から1/2/3（以降3）の一括設定、逆順・同一列の共用、`direct` 指定による土圧の再反転防止は維持した。CLIの既定KG4/5/6も変更していない。

## 利用例

GUIでは左SDCと対象NDUを指定し、モデル図を確認してKG1・2・3をチェックする。この実ファイルでは全杭31 mで候補は一致する。右押しボタンを押すと `1:3 2:2 3:1`、左押しボタンでは `1:1 2:2 3:3` になる。

個別CLIではSDC、NDU、対象KGを明示する。たとえば先端だけを確認する場合:

```powershell
.venv\Scripts\python.exe -B -X utf8 scripts\fill_pile_tip_suppot_info.py `
  --sdc "test\今町橋りょう4P(左).sdc" `
  --ndu "test\今町橋りょう4P(C方向･右押し→).ndu" `
  --groups 1:3 2:2 3:1
```

土圧CLIでGUIと同じ列を直接使用する場合は `--push-direction direct` を指定する。周面CLIでモデルを保存する場合は従来どおり `--profile existing-screen` を指定する。

### GUIテストの後片付け

最初の全体実行では、以前のGUIテストが残したTk変数の循環参照が読込ワーカーのGCで回収され、`Variable.__del__` がメインスレッド以外で実行されて追加GUIテストが時間切れになった。新しいGUIテストの前後で `gc.collect()` をTk所有スレッド上で実行するよう修正し、全193件の成功を確認した。アプリの待ち時間を伸ばして回避する変更はしていない。

先端パーサーの既存7テストは、関数内にネストされていたため発見されていなかった。`ParserTests(unittest.TestCase)` に戻し、すべて成功した。
